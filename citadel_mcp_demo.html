Context
Why MCP matters for banking AI
🧩
Model Context Protocol (MCP)
An open standard that lets AI models (Claude, GPT, Gemini) call tools and access data sources in a governed, structured way — instead of being limited to what's in the prompt.
🏦
Why it matters for banking
Compliance officers need to ask questions and take actions in one interface — without copy-pasting between systems. MCP lets the AI agent freeze accounts, file SARs, and escalate cases as first-class tool calls.
🔒
Security requirement
Every tool call must be authenticated, authorised to the right role, and auditable. OAuth scopes and Snowflake's RBAC ensure a read-only analyst can't call the freeze account tool.
🏗️
Snowflake-native MCP
CREATE MCP SERVER in Snowflake wraps any stored procedure or Cortex Agent as a governed MCP tool — no infrastructure, no custom server, no deployment pipeline.
CITADEL's contribution: The first banking-grade MCP integration pattern on Snowflake — separating read (AI query) from write (regulatory action) into two OAuth-scoped servers.

Security
OAuth security model — principle of least privilege
Reader integration
CREATE SECURITY INTEGRATION CITADEL_MCP_READER_OAUTH TYPE = OAUTH OAUTH_CLIENT = 'PUBLIC' OAUTH_GRANT = 'CLIENT_CREDENTIALS' OAUTH_CLIENT_RSA_PUBLIC_KEY = ... OAUTH_ALLOWED_AUTHORIZATION_ENDPOINTS = ... ENABLED_ROLES = (CITADEL_MCP_READER_ROLE) OAUTH_ALLOW_NON_TLS_REDIRECT_URI = TRUE;
Reader role grants: SELECT on RISK_FLAGS, ACCOUNTS, TRANSACTIONS, CREDIT_EXPOSURES, LIQUIDITY_POSITIONS, POLICY_DOCS · USAGE on CITADEL_AGENT, CITADEL_SEARCH_SVC, CITADEL_RISK_INTELLIGENCE
Action integration
CREATE SECURITY INTEGRATION CITADEL_MCP_ACTION_OAUTH TYPE = OAUTH OAUTH_CLIENT = 'PUBLIC' OAUTH_GRANT = 'CLIENT_CREDENTIALS' ENABLED_ROLES = (CITADEL_MCP_ACTION_ROLE) OAUTH_ALLOW_NON_TLS_REDIRECT_URI = TRUE;
Action role grants: USAGE ON PROCEDURE FILE_SAR_DRAFT, FLAG_ACCOUNT, ESCALATE_CASE · No SELECT on base tables (cannot bypass proc logic)
Credential retrieval
SYSTEM$SHOW_OAUTH_CLIENT_SECRETS(
'CITADEL_MCP_READER_OAUTH')
Token flow
Client credentials → Snowflake token server → short-lived JWT → MCP request header Authorization: Bearer …
Audit trail
Every MCP action call goes through the stored proc → AUDIT_LOG. OAuth token usage tracked in Snowflake ACCESS_HISTORY.

Deep Dive
Request flow — from CoCo to AUDIT_LOG
sequenceDiagram
  actor U as 🧑 Analyst (CoCo)
  participant OA as OAuth Server
  participant MS as MCP Server
  participant AG as CITADEL_AGENT
  participant PR as Stored Proc
  participant AL as AUDIT_LOG

  U->>OA: client_credentials(CLIENT_ID, CLIENT_SECRET)
  OA-->>U: access_token (JWT, short-lived)
  U->>MS: POST /tools/call  Authorization: Bearer token
  MS->>MS: Validate token · check ENABLED_ROLES
  alt AI Query (citadel-ai)
    MS->>AG: Run CITADEL_AGENT with message
    AG-->>MS: Streamed response (SQL + RAG results)
    MS-->>U: MCP result (cited answer)
  else Action Call (citadel-actions)
    MS->>PR: CALL FILE_SAR_DRAFT(flag_id, notes)
    PR->>PR: Role check · AI narrative · UPDATE/INSERT
    PR->>AL: INSERT audit entry (immutable)
    PR-->>MS: VARIANT result
    MS-->>U: MCP result (success + filing_id)
  end
Token lifetime
OAuth tokens are short-lived JWTs. Each MCP call requires a valid token. CoCo auto-refreshes before expiry.
Role enforcement
MCP server validates the role from the token. Then each stored proc re-checks CURRENT_ROLE() inside. Double enforcement.
Audit trail
Every action proc writes to AUDIT_LOG via INSERT ... SELECT FROM (SELECT 1). No role has DELETE on that table.

Security Architecture
Defence in depth — 5 security layers
1️⃣
OAuth Client Credentials
Every MCP request must carry a valid Snowflake OAuth token. Invalid or expired tokens are rejected at the MCP gateway before any Snowflake code runs.
2️⃣
Snowflake RBAC Roles
Reader role ≠ Action role. An analyst with CITADEL_MCP_READER_ROLE cannot call action tools — the action OAuth integration only allows CITADEL_MCP_ACTION_ROLE.
3️⃣
In-proc Role Check
Each stored proc checks CURRENT_ROLE() on entry. Even if the MCP server is bypassed (direct CALL), the proc refuses unauthorized roles.
4️⃣
Column + Row Masking
PII columns (national_id, full_name, account_number) are masked even inside the agent. Row access policies restrict which regulatory filings each role sees.
5️⃣
Immutable AUDIT_LOG
INSERT-only. No Citadel role has DELETE or UPDATE on AUDIT_LOG. Every action call produces a tamper-proof, timestamped entry — BCBS 239 Principle 2 compliant.
🏆
Net result
A CoCo user can only do what their Snowflake role allows. The MCP layer adds no new attack surface — it's a governed API gateway over existing Snowflake security controls.
